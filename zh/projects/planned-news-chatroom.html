把新闻做成聊天室：事实与观点分离

一条 LLM pipeline / agent，解析新闻报道、把事实与观点分开，并以聊天室式的界面呈现：房间标题是底层事实，“发言者”是陈述各自观点的媒体，读者是旁观者而非参与者。

核心想法（我自己的话）

  • 新闻报道把事实和观点混在同一段文字里。正因为二者交织，读者的情绪和认知会被观点左右，真正的事实反而被忽视或淡化。
  • 用 LLM 把二者分开，然后改变呈现方式：每个事实/事件一个聊天室。每家媒体是一个发言者，发表自己的看法。读者只旁观。
  • 例子：俄乌战争 —— 双方持有相互冲突的叙事，对同一事件的报道大相径庭。许多有争议的话题都适合这种形式。

为什么这种形式有效

  • 把事实放在标题、观点放在聊天里，让这种分离看得见，而不是藏在文字之中。
  • 把几家媒体并排展示，把“新闻”变成“每家媒体各自声称了什么”，这才是正确的心智模型。
  • 旁观者立场（没有回复框）让读者不去争辩，也让产品不会变成评论区。

初步的系统大纲

Pipeline

  1. Ingest（接入） —— 从多家媒体收集某一话题的文章（RSS、公开 API、允许的情况下做抓取）。存储来源、媒体、时间戳、全文。
  2. 事件聚类 —— 把关于同一底层事件的文章分为一组（embedding + LLM 确认）。
  3. 事实 / 观点分离 —— 对每篇文章提取：
  • 事实陈述（谁 / 什么 / 何时 / 何地，附带引用的证据片段），
  • 观点 / 立场表述（评价性语言、推测、对动机的归因），
  • 带倾向性用语的标记。
  1. 事实调和 —— 跨媒体把陈述合并为该事件的“公认事实”与“有争议的说法”（注明谁说了什么）。房间标题来自公认事实；有争议的说法照实标示。
  2. 渲染 —— 聊天室：标题 = 事实；消息 = 每家媒体的观点/立场，用其自身的口吻、带时间戳；可展开的引用可追溯到原句。

UI

  • 房间列表（每个事件一个），按时间或争议程度排序。
  • 房间视图：置顶的事实标题；有争议说法面板；按媒体划分的消息流，带媒体头像；可点击跳转到来源。
  • 没有输入框。对于持续发展的事件，也许加一个“自昨天以来有什么变化”的 diff。

关键问题

  • 事实/观点并不是干净的二元划分；需要一套 rubric（评判标准）和评估集。考虑分三类：可验证的事实、有归属的说法、观点/立场。
  • 来源覆盖与访问权限（付费墙、ToS）；先从可免费获取的媒体和官方声明开始。
  • 分离模型本身的偏见 —— 通过始终展示证据片段、以及报告各媒体的统计数据而非裁决来缓解。
  • 多语言：同一事件的俄语/乌克兰语/中文/英文报道是最有说服力的 demo，也是最难的接入问题。

里程碑

  1. 单一话题、3–5 家媒体、一个手选的事件；运行分离 prompt，目测质量。
  2. 建立评估集（约 50 句，标注为事实 / 说法 / 观点）；调优 prompt。
  3. 为一个话题自动化接入 + 聚类。
  4. 聊天室 UI（静态站点即可）；每日重新生成。
  5. 扩展话题；加入“有争议的说法”调和。

技术备注

  • Python pipeline、结构化的 LLM 输出、Postgres 存储、embedding 做聚类；简单的 Web 前端。
  • 复用 JHA 项目在抓取/dedup 上的经验。
