个性化每日新闻摘要

一份每日摘要，从免费来源 —— GitHub Trending、各大 AI 公司的最新产品、新的软件发布 —— 抓取我关心的话题，做摘要，每天早上交付一页易读的内容。

核心想法（我自己的话）

  • 来源都是免费公开的：GitHub Trending、AI 公司的公告、软件发布的 feed。
  • 按我的兴趣个性化；做好摘要，让我只读一份 digest（摘要）而不是十几个网站。

初步大纲

来源（初始列表）

  • GitHub Trending（每日 / 每周，按感兴趣的语言 —— Python、TypeScript 等）。
  • AI 公司：官方博客 / changelog / release notes（Anthropic、OpenAI、Google DeepMind、Meta AI、Mistral 等），有 RSS 的走 RSS。
  • 软件发布：我在用的工具的 GitHub Releases feed；Hacker News 首页作为兜底。
  • 以后可选：arXiv 分类、Product Hunt、精选的 newsletter。

Pipeline

  1. Fetch（抓取） —— 优先 RSS/Atom，只在没有 feed 时才做 HTML 抓取；遵守限速和 robots。
  2. Dedup + 过滤 —— 丢弃之前见过的条目；对照一份“兴趣画像”（一段描述我关心什么的短文本，可由我编辑）给相关性打分。
  3. 摘要 —— 每条：一句话说明是什么、为什么对我重要、链接。按板块分组。
  4. 编排 —— 一个单页的 Markdown/HTML 页面；“今日前 5”放在顶部，其余在下面。
  5. 交付 —— 邮件、本地文件、Telegram/Discord 消息，或一个静态页面。每天定时运行（cron / 定时任务）。

个性化的想法

  • 纯文本的兴趣画像 + 对条目点赞/点踩，随时间调整排序。
  • 跟踪“我点开了什么”，学习我实际会读的内容。
  • 在每日之外再加一份每周汇总。

关键问题

  • 多少 LLM 摘要值得花钱，还是只要标题 + 相关性排序就够？（先从便宜的做起：先排序，只对前 N 条做摘要。）
  • 我想在哪里读它 —— 邮件、聊天应用，还是浏览器标签页？
  • 它是否应该与新闻事实/观点项目（想法 04）共用接入层？fetch/dedup 层大概率是的。

里程碑

  1. 一个脚本，拉取 GitHub Trending + 3 个 RSS feed，打印一份 Markdown 摘要。
  2. 加入 dedup 存储（SQLite）和兴趣画像排序。
  3. 对排名靠前的条目加 LLM 摘要；每日定时运行。
  4. 选定的交付渠道；反馈按钮。

技术备注

  • Python、feedparser/httpx、SQLite、一次小规模的 LLM 调用做摘要；cron 或托管的定时任务。
  • 复用 JHA 的抓取/dedup 模式。
