Few-shot 分类器应该信任哪个 backbone？

Prototypical Networks（原型网络）按特征空间中到各类均值的距离进行分类，这意味着 feature extractor 就是整个模型。 我从零开始训练了 ResNet-18、DenseNet-121 和 ConvNeXt-T 作为 feature extractor，在 CUB 数据集上做 5-way 5-shot 分类（每个 episode 5 个类别、每类 5 个支持样本），对 data augmentation 做了 ablation，并记录了我最初尝试的两种分类器改进方案——两者都没有奏效。

问题设定

few-shot 分类要求模型仅凭少量带标签的样本识别新类别——比如每类五张从未见过的鸟类图片。标准的表述是 episodic（回合式）的： 每一步训练采样 N 个类别，给模型每类 K 张带标签的图片（support set），再让它对另外 Q 张进行分类（query set）。 这里 N = K = Q = 5，每个 epoch 从 CUB-200 的训练集采样 500 个 episode，从验证集采样 50 个。

Prototypical Networks 是能奏效的最简单方案：把支持图片和查询图片送入 CNN，把每个类别的支持特征取平均作为原型， 再按哪个原型最近来给查询样本分类。没有需要学习的分类头。CNN 就是整个模型，于是"选哪个 CNN"就成了整个问题。

一个值得说明的选择。三个 backbone 都从随机初始化开始训练——用的是 resnet18()，而不是 resnet18(weights=…)。这使得绝对准确率低于使用 ImageNet 预训练特征时的水平，但也让架构之间的比较更干净：没有任何东西是继承来的。

如何解读

ResNet-18 之所以是主力模型，是有原因的：单位训练时间内的准确率遥遥领先，曲线也最稳定。 DenseNet-121 在准确率上略胜一筹——高出两个百分点，超出误差范围——而且去掉 data augmentation 后损失小得多（−8.8 对 −12.6）， 这是一个模型能从更少数据中泛化的标志。代价是尽管参数更少，训练速度却慢了一倍；密集连接意味着每一层都要看到之前所有的特征图， 真正付出代价的是激活值，而不是权重。

ConvNeXt-T 的表现不如它自己的前辈。报告的解读是：它的 7×7 卷积核扩大了感受野，却牺牲了局部细节， 而小数据集上基于距离的分类器恰恰需要那些被平均掉的细节。为 ImageNet 规模数据调优的现代架构，并不自动就是每个 episode 25 张图片场景下更好的架构。

ablation 干净利落地回答了一个问题：data augmentation 在这里不是可选项。去掉它会损失 9 到 13 个百分点——比任意两个 backbone 之间的差距都大。

我最初尝试了什么，以及为什么没有奏效

最初的计划并不是比较 backbone，而是改进分类器。有两个想法一直推进到了实现阶段，我才明白它们为什么无法按原设想成立； 两者都写进了报告的附录，我认为它们也应该出现在这个页面上。

核化原型（Kernelised prototypes）

最近原型分类是特征空间中的线性决策规则。如果类别在该空间中不是线性可分的，经典的补救办法是核方法——映射到更高维的空间，让它们变得可分。 问题在于：CNN 输出的特征本身已经处在 512 维或更高的空间中。在这样的宽度下，线性不可分并不是瓶颈，核方法没有什么可补充的。 如果说有什么有用的方向，反而是相反的——一个更小、更锐利的特征空间。

注意力加权原型（Attention-weighted prototypes）

简单均值把每个支持样本都视为同样可信。每类五个样本时，一个坏样本就会把原型朝它所在的位置拉动五分之一的距离——本页顶部的图正演示了这一点。 这个想法是按支持特征与查询样本的相似度对其加权，借用 Transformer 的 softmax(QKᵀ/√d)·V，以查询样本为 Q、原型为 K、支持特征为 V。

问题在于：Transformer 中这三个矩阵在构造上共享同一个维度，而这里它们并不共享——有 N 个原型、N·K 个支持特征和 N·Q 个查询样本——所以公式无法按原样套用。它需要一种形状不同的注意力机制，这是一个真正的研究问题而非课程项目能解决的，我如实说明了这一点，而没有强行凑出来。

为什么保留这些失败。从"改进分类器"转向"刻画 feature extractor"，是因为前两个想法已经被理解得足够透彻、足以被排除，而不是因为它们被放弃了。 知道为什么显而易见的修复方案并不适用，是我从这个项目中学到的最主要的东西。

完整的模型

整个分类器就是一个模块。backbone 的分类头被替换为 nn.Flatten()，使其输出原始特征；原型是类别均值； 输出是负的欧氏距离，cross-entropy 会把它变成类别上的 softmax。 

class PrototNet(nn.Module):
    def __init__(self, FE):
        super().__init__()
        self.FE = FE                              # 任意 torchvision backbone，去掉分类头

    def forward(self, images_K, labels_K, images_Q):
        features_K = self.FE(images_K)            # 支持特征，(N*K, D)
        features_Q = self.FE(images_Q)            # 查询特征，(N*Q, D)

        prototypes = torch.stack([               # 每类一个均值 -> (N, D)
            features_K[labels_K == c].mean(0)
            for c in labels_K.unique()
        ])
        return -torch.cdist(features_Q, prototypes)   # logits：越近越可能

FE = resnet18()                                   # 从零开始：不传 weights=
FE.fc = nn.Flatten()                              # 输出特征，而不是类别
model = PrototNet(FE).cuda()

# 一个回合：
loss = nn.CrossEntropyLoss()(model(x_K, y_K, x_Q), y_Q)
