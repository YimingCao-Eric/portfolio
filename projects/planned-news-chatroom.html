News as a chat room: facts vs. opinions

An LLM pipeline / agent that parses news reports, separates facts from opinions, and presents them in a chat-room-style interface: the room title is the underlying fact, the "speakers" are media outlets stating their viewpoints, and the reader is an observer, not a participant.

Status: Recorded. This is an outline, not an implementation — recorded so the idea and its open questions aren't lost. It will change as I think it through. Created 2026-09-12 · last updated 2026-09-12.

Core idea (in my words)

  • News coverage blends facts and opinions in the same text. Because they're interwoven, the reader's emotions and perceptions get swayed by the opinions and the actual facts get overlooked or downplayed.
  • Separate the two with an LLM, then change the presentation: a chat room per fact/event. Each outlet is a speaker posting its take. The reader watches.
  • Example: the Russia–Ukraine war — both sides hold conflicting narratives and report the same events very differently. Many controversial topics fit this format.

Why this format works

  • Putting the fact in the title and the opinions in the chat makes the separation visible instead of hidden inside prose.
  • Seeing several outlets side by side turns "the news" into "what each outlet claims", which is the correct mental model.
  • Observer stance (no reply box) keeps the reader from arguing and keeps the product from becoming a comment section.

Proposed system outline

Pipeline

  1. Ingest — collect articles on a topic from multiple outlets (RSS, public APIs, scraping where allowed). Store source, outlet, timestamp, full text.
  2. Event clustering — group articles that are about the same underlying event (embeddings + LLM confirmation).
  3. Fact / opinion separation — per article, extract:
  • factual claims (who / what / when / where, with quoted evidence spans),
  • opinion / framing statements (evaluative language, speculation, attribution of motive),
  • loaded-language flags.
  1. Fact reconciliation — across outlets, merge claims into the event's "agreed facts" vs. "disputed claims" (with who says what). The room title comes from the agreed facts; disputed claims are shown as such.
  2. Render — chat room: title = fact; messages = each outlet's opinion/framing, in their own voice, timestamped; expandable citation back to the original sentence.

UI

  • Room list (one per event), sorted by recency or controversy.
  • Room view: pinned fact header; disputed-claims panel; message stream by outlet with outlet avatar; click-through to source.
  • No composer. Possibly a "what changed since yesterday" diff for long-running stories.

Key questions

  • Fact/opinion is not a clean binary; need a rubric and evaluation set. Consider three buckets: verifiable fact, attributed claim, opinion/framing.
  • Source coverage and access (paywalls, ToS); start with freely available outlets and official statements.
  • Bias in the separator model itself — mitigate by always showing the evidence span, and by reporting per-outlet stats rather than verdicts.
  • Multilingual: Russian/Ukrainian/Chinese/English coverage of the same event is the strongest demo and the hardest ingestion problem.

Milestones

  1. Single topic, 3–5 outlets, one hand-picked event; run the separation prompt and eyeball quality.
  2. Build an eval set (~50 sentences labelled fact / claim / opinion); tune prompts.
  3. Automate ingest + clustering for one topic.
  4. Chat-room UI (static site is fine); daily regenerate.
  5. Expand topics; add "disputed claims" reconciliation.

Tech notes

  • Python pipeline, structured LLM outputs, Postgres for storage, embeddings for clustering; simple web front end.
  • Reuse the scraping/dedupe lessons from the JHA project.
