Which backbone should a few-shot classifier trust?

Prototypical Networks classify by distance to a class mean in feature space, which means the feature extractor is the whole model. I trained ResNet-18, DenseNet-121 and ConvNeXt-T from scratch as extractors for 5-way 5-shot classification on CUB, ran an ablation on augmentation, and documented the two improvements to the classifier I tried first — neither of which worked.

In the real model the points live in a 512- or 1024-dimensional space produced by a CNN, not on a plane — but the arithmetic is identical, and so is the weakness. Try 1-shot: with a single support example per class, the prototype is that example, noise and all.

The setup

Few-shot classification asks a model to recognise new categories from a handful of labelled examples — five images per class, say, of bird species it has never seen. The standard formulation is episodic: each training step samples N classes, gives the model K labelled images per class (the support set) and asks it to classify Q more (the query set). Here N = K = Q = 5, with 500 episodes per epoch sampled from CUB-200's training split and 50 from its validation split.

Prototypical Networks are the simplest thing that works: push support and query images through a CNN, average each class's support features into a prototype, and classify a query by which prototype is nearest. There is no classification head to learn. The CNN is the entire model, which makes "which CNN?" the entire question.

One choice worth flagging. All three backbones were trained from random initialisation — resnet18(), not resnet18(weights=…). That makes the absolute accuracies lower than you'd see with ImageNet-pretrained features, and makes the comparison between architectures cleaner: nothing is inherited.

Reading it

ResNet-18 is the workhorse for a reason: best accuracy per hour by a wide margin, and the most stable curve. DenseNet-121 edges it on accuracy — two points, outside the error bars — and loses far less when augmentation is removed (−8.8 vs −12.6), which is the signature of a model that generalises from less. The cost is that it trains twice as slowly despite having fewer parameters; the dense connections mean every layer sees every earlier feature map, and the activations, not the weights, are what you pay for.

ConvNeXt-T underperformed its own predecessor. The report's reading is that its 7×7 kernels widen the receptive field at the cost of local detail, and a distance-based classifier on a small dataset needs exactly the detail being averaged away. A modern architecture tuned for ImageNet-scale data is not automatically a better architecture for 25 images per episode.

The ablation settles one question cleanly: augmentation is not optional here. Removing it costs 9 to 13 points — larger than the gap between any two backbones.

What I tried first, and why it didn't work

The original plan was not a backbone comparison. It was to improve the classifier. Two ideas made it to implementation before I understood why they couldn't work as stated; both are in the report's appendix, and I think they belong on this page too.

Kernelised prototypes

Nearest-prototype classification is a linear decision rule in feature space. If classes aren't linearly separable there, the classical fix is a kernel — map to a higher dimension where they are. The flaw: a CNN's output features already sit in 512 or more dimensions. Linear inseparability is not the bottleneck at that width, so a kernel has nothing to add. If anything the useful direction is the opposite — a smaller, sharper feature space.

Attention-weighted prototypes

A plain mean treats every support example as equally trustworthy. With five examples per class, one bad one moves the prototype a fifth of the way toward wherever it sits — the figure at the top of this page shows exactly that. The idea was to weight support features by their similarity to the queries, borrowing the transformer's softmax(QKᵀ/√d)·V, with queries as Q, prototypes as K and support features as V.

The flaw: in the transformer the three matrices share a dimension by construction. Here they don't — there are N prototypes, N·K support features and N·Q queries — so the formula can't be applied as written. It needs a differently-shaped attention, which is a real research problem rather than a course project, and I said so instead of forcing it.

Why keep the failures. The pivot from "improve the classifier" to "characterise the extractor" happened because the first two ideas were understood well enough to rule out, not because they were abandoned. Knowing why the obvious fix doesn't apply is most of what I took from this project.

The model, in full

The entire classifier is one module. The backbone's classification head is replaced with nn.Flatten() so it emits raw features; prototypes are class means; the output is negative Euclidean distance, which cross-entropy turns into a softmax over classes. 

class PrototNet(nn.Module):
    def __init__(self, FE):
        super().__init__()
        self.FE = FE                              # any torchvision backbone, head removed

    def forward(self, images_K, labels_K, images_Q):
        features_K = self.FE(images_K)            # support features, (N*K, D)
        features_Q = self.FE(images_Q)            # query features,   (N*Q, D)

        prototypes = torch.stack([               # one mean per class -> (N, D)
            features_K[labels_K == c].mean(0)
            for c in labels_K.unique()
        ])
        return -torch.cdist(features_Q, prototypes)   # logits: nearer is likelier

FE = resnet18()                                   # from scratch: no weights=
FE.fc = nn.Flatten()                              # emit features, not classes
model = PrototNet(FE).cuda()

# one episode:
loss = nn.CrossEntropyLoss()(model(x_K, y_K, x_Q), y_Q)

Lightly tidied from the notebook — the original builds the prototype tensor with a loop and torch.cat; this is the same computation.

Episodes are sampled with easyfsl's TaskSampler, which handles the N-way K-shot bookkeeping. Everything else — training loop, evaluation, augmentation pipelines, the three backbone swaps and the ablation — is in the notebook.
